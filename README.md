# Maxing Solar · 泰国光伏智能报价系统

## 合同生成功能

报价页新增独立项目名称与甲方名称。点击「生成施工合同」，核对签约日期、甲方资料、乙方注册名称、两个指定收款账户，填写首款比例后下载 Word。合同名称、项目地址、实际容量、含税总价、中泰文金额文字、首款与尾款均来自当前报价。金额按分计算，两笔款项合计严格等于合同总价。备案费用仅作为总价内拆分，不再叠加收费。合同 COD 期限默认180自然日，与现场施工工作日分开。

正文称谓统一为甲方 `ผู้ว่าจ้าง`、乙方 `ผู้รับจ้าง`。生成的无电池合同明确电池质保不适用。原模板第3.2条存在中泰文含义不一致，尚未重写实质条款，生成页有核对提示。

JSZip 已随应用提供，不需在线加载。Word 模板采用 OOXML 字段替换，保留原段落、表格、样式和页脚。公开 GitHub 只提供应用逻辑，不发布用户合同及银行资料；私有部署需要自行提供 `dist/contract-template.docx`、`dist/contract-defaults.json`。后者的字段对应合同页公司与账户输入框。不要将这些私有文件提交至公开仓库。

合同生成在浏览器本地执行；只在主动点击保存公司资料时把乙方配置保存至本机。客户身份证不保存在报价历史。JSON 报价历史包含项目名称，旧历史记录恢复后可补填项目名称。

可直接部署的中文单页应用，无需后端、无需构建。所有报价记录保存在当前浏览器，未上传客户账单。GitHub 源码不包含客户资料。

## 运行

需要 Node.js 20+。运行 `npm start`，打开 http://127.0.0.1:4173 。运行 `npm test` 验证核心计算。部署时将 `dist/` 作为静态网站目录。

## 已实现

- 按屋顶、按电费 / 实际 kWh、双重约束推荐、手动容量四种模式。
- 按整块组件向下取整，用实际 Wp 判断单价：**≥50 kWp = 15.5 THB/W，<50 kWp = 21.5 THB/W**。整套系统按对应档位报价，已含税，不加第二次 VAT，不含电池。
- 组件数量、屋顶面积占用、发电量、自用节省、简单回本、现场施工天数。
- 上传图片、PDF、TXT；TXT 和粘贴文字可提取有明确标签的账单数据；图片提供泰文 / 英文 OCR 后人工确认；PDF 当前仅作查看核对，不支持 PDF OCR。图片 OCR 使用 Tesseract.js 5.1.1，需要联网下载识别组件与模型，识别在浏览器执行。图片识别和字段提取准确率尚未用真实账单验证。
- 本机报价历史、恢复、JSON 导出 / 全部备份、浏览器打印 / 存为 PDF。
- 可编辑组件、发电、施工和报价参数。打印报价包括客户、地址和关键假设。

## 计算口径

屋顶容量 = floor(屋顶总面积 × 可用比例 ÷ 每块组件占用面积) × Wp/1000。

没有实际 kWh 时，月用电量 = 月电费 ÷ 估算购电电价；不是按电力公司分时阶梯 / Ft / 固定费计费模型反推。

需求容量 = 月用电量 ×12 × 白天用电比例 × 目标覆盖率 ÷ (年单位装机发电量 × 发电自用比例)。智能推荐取屋顶上限和需求容量较小值；仅填写一种数据时使用该数据。所有容量按整块组件向下取整。

年发电量 = 实际 kWp × 年单位装机发电量。自用电量 = min(年发电量 × 自用比例，年用电量 × 白天比例)。节省 = 自用电量 × 估算电价，不计算余电出售。回本 = 含税报价 ÷ (年节省 − 年运维预留)。没有有效用电数据时不输出回本。

现场工期 = 准备调试天数 + ceil(实际 kWp ÷ 团队日安装 kWp) + 缓冲天数。不含设备采购、审批及电力公司并网等待时间。

默认 625 Wp、2.8m²/块、1400 kWh/kWp/年、自用90%、日安装12 kWp、准备调试2天、缓冲2天、运维1%均为可修改的示例假设，不是现场设计或发电保证。

## 当前边界

本版本用于初步业务报价。尚未接入云端数据库、账户权限、地图 / 卫星屋顶测量、现场遮挡仿真、正式物料清单 / 逆变器匹配、合同签章或真实电力公司接口。不会自动添加结构加固、变压器等额外费用；需现场核对范围。

当前浏览器记录最多保留100份；未包含原始账单文件，跨设备需导出备份。清理浏览器数据会删除本机记录。对外正式使用前应确认发电假设、施工效率、报价范围及真实账单识别效果。
